# Mac 资源监控

每 15 秒取整机 CPU 差分、内存压力及前 15 项进程组。进程使用相邻采样的累计 CPU 时间差；100% 单核代表一个逻辑核心，同时展示除以逻辑核心数后的整机占比。整机与进程窗口长度分别记录，采集不是原子操作，数值不要求精确相加。

后台任务按既有 jobs 控制器的 launchd Label 和 PID/PPID 链归属，深层子进程算入所属任务，每个 PID 只计一次。其余进程按最外层 App 路径汇总，模拟器作为一组。记录前 15 个高 CPU 进程的 PID、父链、启动时间，以及所有采样中识别到的运行任务，避免多个 Python 任务混为一组。没有 PID 的等待任务不算正在执行。

首次出现、PID 重用、计数回退的进程要到下次可比采样才计 CPU；已退出或两次采样之间完成的进程无法完整测量。覆盖数字明确记录，含未测量进程的组以 `≥` 显示已知部分。父链只作归属证据，不重复累加子树；JSON 的 top、top_processes、managed_jobs 是不同视图，不能跨列表相加。RSS 合计可能重复计算共享页，只作占用估算。历史旧日志缺少 PID，不能靠当前进程树补写过去的任务归属。

**自动弹窗仅在整机 CPU ≥95% 连续满 60 秒时触发。** 任一采样低于 95%、CPU 读数无效，或间隔超过正常采样周期的 1.5 倍，都会重新计时；不能用“窗口内 80% 时长达标”代替连续达标。内存、WindowServer、单进程和热压力异常继续记录事件与分析，不会单独触发自动弹窗。菜单栏手动查看不受这道门槛限制。

以下是**事件记录**条件，默认要求窗口内至少 80% 时长满足条件，并且当前采样仍异常；一次短暂下降不会抹掉长期问题。睡眠或采样断档会重置事件窗口。

| 条件 | 默认窗口 |
|---|---|
| 整机 CPU ≥90% | 60 秒 |
| 整机 CPU ≥75% | 120 秒 |
| WindowServer ≥150% 单核 | 120 秒 |
| 同一进程实例 ≥95% 单核 | 180 秒；不同 PID/启动时间不继承 |
| 内存 warning，且 CPU ≥60% 或换页合计 ≥1 MB/s | 180 秒 |
| 内存 critical | 45 秒 |
| 热压力 serious / critical | 120 / 60 秒 |

持续过载触发组合消失 60 秒后结案；内存 warning 但 CPU/换页已低可以恢复，unknown/critical 不据称正常。事件留存与弹窗冷却分离：已显示的同级提示默认间隔 30 分钟，严重度升级可以提前提示；启动/呈现失败 30 秒后可重试，不消耗正常冷却。所有自动重试和升级提示仍须满足 CPU ≥95% 连续满 60 秒。

菜单栏 **“负载”** 可随时查看当前原因、推荐操作和历史事件。提示使用不激活应用的面板，不抢键盘焦点，120 秒后自动收起；建议和证据继续保留。面板说明观察事实、可能原因、处理影响以及可以复述的原理，默认推荐保留工作、查看证据，所有退出项默认不选。确认处理后给出结果；退出请求与实际退出分别记录，等待保存或拒绝退出不强杀。

支持“一键勾选推荐项”：按当前异常原因，选择 CPU ≥30% 单核或 RSS ≥512 MB 的普通应用，最多三项，显示具体数值依据；排除系统、终端、网络、文稿/代码编辑器、身份不确定和过期记录。没有合格项就不推荐。选中本身不执行退出；点击“关闭已选”即请求正常退出，不再多弹一个确认框，应用自身的保存提示保留。

仅在用户选中并点击“关闭已选”后，才向符合条件的普通 GUI 应用请求正常退出、结束本用户输入法原实例，或暂停明确支持的图谱任务（`ctl resume md-index-graph` 可恢复）。系统服务、网络连接、终端及其任务受保护；未知后台进程保留诊断，不把高 CPU/PPID=1 当作死亡证据。已经僵死的进程不能靠重复 kill 释放资源，应分析父进程回收问题。取消、忽略、过期快照、已恢复事件不执行退出。

动作绑定**采样当时**的内核 PID、启动秒/微秒、UID 与路径，点击时重新核对实例、父链、保护标记和时效。PID 复用或应用重启会阻止旧建议执行，不把旧路径重新绑定新应用。预览模式永不退出应用。

自动清理仅限监控自己创建且已超时的采样子进程组、未呈现的提示子进程，记录结果。采样命令有 3 秒超时及输出上限；不会自动关闭用户应用、删除应用或业务文件。日常采样增加换页速率、交换存量、压缩内存、热压力、屏幕信息及采集健康；CPU 与 RSS 分开排序。没有远端模型调用、上传或通知外发。

新事件开始时异步限量采集最多两个同用户、身份仍相符的进程堆栈；每个 2 秒，命令 8 秒上限，产物总量低于 4 MB。系统进程无权限、目标退出或证据过期会明确记录，不提权、不重复采样。堆栈提供执行位置线索，不自动宣称已证明根因。动作完成后持续采样，记录是否达到恢复条件；恢复时间相关不自动等同于修复因果。

安装：`python3 scripts/system/resource_watch/install.py`，随后 `~/Dev/jobs/ctl resume resource-watch`。已有安装更新用 `install.py --build-only`，仅原子替换二进制，保留 plist 和 config；再用 `~/Dev/jobs/ctl reload resource-watch` 只重载监控本身。暂停：`~/Dev/jobs/ctl pause resource-watch`。

记录只存在本机 `~/Library/Application Support/ResourceWatch/`（目录权限 700）：

- `latest.json`：当前快照。
- `samples-YYYY-MM-DD.jsonl`：每次采样，自动保留 14 天。
- `actions.jsonl`：提示及用户请求退出记录；退出请求不是已退出证明。
- `incidents/<id>.json` / `.md`：一次异常的原因、推荐操作、告警前 24 条采样、首次/峰值/恢复采样和最多 120 个一分钟节点；默认保留 90 天。重启中断标为 interrupted，不冒充恢复。
- `incidents/<id>-diagnostics.json` / `<id>-sample-<pid>.txt`：一次事件的堆栈、权限与身份检查回执，随事件到期清理。
- `latest-advice.json` / `.md`：当前建议，历史事件另存；窗口收起后仍可查。
- `prompt-state.json` / `alert-state.json`：提示呈现回执与跨重启冷却状态。事件包含 launched/presented/launch_failed/cancelled/timed_out/action_result；不会再把尝试启动当成成功显示。
- `config.json`：采样间隔、阈值、持续时长、冷却、保留天数；修改后 reload。

不收集命令参数、网页标题、文档内容。包含本机程序路径。退出确认后按原应用实例发请求，避免 PID 复用误杀。

只读诊断：二进制 `--diagnose 2`（可选 1–60 秒）向 stdout 输出 JSON，不写状态、取 daemon 锁或显示界面。可与单个常驻监控并行，不会成为第二个常驻监控。`--once` 会写一次真实快照后退出；`--preview` 显示真实快照，所有退出动作禁用（确认也不会退出应用）。正常监控无参数。

在本目录运行 `python3 tests/run.py`，覆盖采样/超时清理、PID与任务保护、策略/冷却、事件持久化、诊断和隔离测试应用的正常退出/拒绝退出。测试应用不会显示工作窗口，也不触及用户应用。

配置扩展键见 `IncidentPolicy.swift`；原有 CPU/持续键只影响事件记录，冷却键继续兼容。自动弹窗单独使用 `prompt_cpu_threshold`（默认 95，最低 95）与 `prompt_sustained_seconds`（默认 60）。`interval_seconds` 默认 15，`retention_days` 默认 14，`incident_retention_days` 默认 90。其他异常仍按持续时间与换页/CPU 组合留证，不因记录事件而自动打扰。
