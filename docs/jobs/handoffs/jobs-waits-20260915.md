## 三个长时间运行的任务

- Git 自动同步：旧PID已完成，新轮次子进程持续更换，前轮9仓已同步。当前有单仓网络连接重置，任务继续下仓。每仓多次网络查询、整轮末尾才输出汇总，因此看起来长时间无进展；保留当前任务与排程。
- 通知队列：单次批处理，非常驻服务。旧进程卡在首次读取队列的SSH，尚未领取任务。原实现只有连接超时和远端curl超时，缺本机SSH总时限，已建立/复用连接可以无限等。修复在原notifhub组件，细节见其本次交接。
- 青龙登录监视：单次检查后的报告上传卡在rsync→SSH；原os.system无总时限。修复在qinglong/report/transport.py，限制连接、空闲与总上传时间，失败保留本地报告供下轮重试。
- 收尾复查时两个旧等待分支都已自行退出，未发送 TERM 或 KILL。通知队列已继续执行后续轮次，launchd 最近退出0；青龙该轮也已退出0。进程退出只证明该轮结束，上传结果仍以原业务日志为准。新版 notifhub CLI 已原子安装并保留可回滚副本；青龙脚本供下轮使用，没有手动触发业务任务。

理解要点：进程在等待网络时CPU可以接近0；持续时间、CPU使用和业务是否完成是三个不同指标。sudo当次授权也不等于后续每次后台任务永久获权。看安装回执才能确认手工升级完成，看新运行回执才能确认下一轮任务结果。
